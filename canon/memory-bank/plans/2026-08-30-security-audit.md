# План аудита безопасности

## Цель

Найти и подтвердить уязвимости в текущем веб-продукте Training Journal: Express API, JWT-аутентификация, SQLite, файловое workspace и клиентские security-flow, а затем выдать отчёт с доказательствами, уровнем риска и точными местами в коде. Исправления не входят в эту задачу без отдельного запроса.

## Критерий готовности

- Проверены auth, authorization/IDOR, input validation, path traversal, CORS/CSRF, rate limiting, secrets, dependency/configuration и client-side exposure.
- Для runtime-зависимых гипотез собраны чистые NDJSON-логи debug-сессии.
- Все подтверждённые находки привязаны к файлу/строке и воспроизводимому сценарию; неподтверждённые явно отмечены.
- Созданы Markdown-отчёт и PDF с одинаковым содержанием.

## Гипотезы

1. **H1 — обход авторизации/IDOR:** API может доверять имени пользователя или идентификатору из URL/body сильнее, чем субъекту JWT, позволяя читать или менять чужие данные.
2. **H2 — слабая граница JWT:** секрет по умолчанию, небезопасная конфигурация cookie/token или недостаточная проверка срока/алгоритма могут позволить подделку или повторное использование токена.
3. **H3 — path traversal в workspace:** пользовательский путь/имя файла может выйти из `WORKSPACE_FILES_ROOT`, раскрывая локальные файлы или позволяя запись вне workspace.
4. **H4 — недостаточная защита API:** CORS, rate limiting, body limits или нормализация входа могут позволить CSRF/brute-force/DoS либо раскрытие лишних ошибок.
5. **H5 — секреты и чувствительные данные:** production-конфигурация, client bundle, логи или ошибки могут раскрывать JWT secrets, пароли, токены или персональные данные.

## Порядок

1. Проверить структуру server/client/config и существующие security tests.
2. Запустить безопасные read-only проверки и добавить временную runtime-телеметрию по H1–H4 без секретов.
3. Очистить debug-log и собрать воспроизведение через dev API/UI.
4. Проанализировать логи и статические доказательства; не называть гипотезу подтверждённой без evidence.
5. Подготовить `audit/security-audit-2026-08-30.md` и PDF.
