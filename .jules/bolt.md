## 2024-05-16 - Optimize React O(N*M) existence checks in App.tsx
**Learning:** Checking for the existence of user-saved exercises against a large list of config exercises using `.every()` and `.some()` inside component renders creates an O(N*M) bottleneck, especially when the component updates frequently. In this case, `missingExercises` and `allSaved` were recalculated continuously. Using `useMemo` to cache a `Set` of lookup keys converts this to an O(1) retrieval pattern. The React Compiler handles dependency tracking natively, but explicit memoization protects performance in environments without it.
**Action:** When finding `.some()` or `.find()` inside mapping/filtering loops like `.every()` or `.filter()`, index the inner list into a `Set` or `Map` using `useMemo` to dramatically improve performance, ensuring fallback values exactly match the original defaults. Always remember that memory instructions specify `yarn lint` or `tsc` might fail due to network limits blocking package downloads, so rely on `yarn test` and visual review.
