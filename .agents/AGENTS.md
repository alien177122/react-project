# Workspace Developer Rules

## Запуск приложения и туннеля

1. **Всегда использовать Docker-контейнеры для запуска:**
   - Перед запуском всегда останавливать и удалять старые контейнеры/орфаны с помощью команды:
     `docker compose --env-file .env.docker down --remove-orphans`
   - Пересобирать и запускать контейнер заново с флагом `--build`:
     `docker compose --env-file .env.docker up --build -d`

2. **Запуск через туннель (Cloudflare):**
   - Всегда запускать приложение сразу через публичный туннель:
     `cloudflared tunnel --url http://localhost:3001`
   - Или использовать встроенный быстрый туннель:
     `npm run public:quick`

## Обработка входящих файлов пользователя

1. **Конвертация документов в Markdown:**
   - Все входящие файлы (PDF, Word, Excel, презентации, изображения), присылаемые пользователем для анализа, должны предварительно обрабатываться через автоматический конвертер MarkItDown на Рабочем столе: `/Users/steve_gordiyenko/Desktop/AI_Shared_Memory`.
   - Использовать, читать и анализировать информацию необходимо строго из полученных результирующих `.md` файлов в папке `converted/` (`/Users/steve_gordiyenko/Desktop/AI_Shared_Memory/converted/`). Это предотвращает «галлюцинации» ИИ из-за сложной бинарной структуры исходных файлов и оптимизирует расход контекстных токенов.

## Тестирование и верификация интерфейса

1. **Использование Maestro для тестирования мобильного веба и приложений:**
   - После любого изменения пользовательского интерфейса (UI/UX) и верстки всегда использовать **Maestro CLI** на симуляторе iOS/Android для верификации.
   - Запускать Maestro-тесты с помощью сценариев YAML (например, из папки скриптов или временных папок), делать скриншоты и проверять отображение на различных табах.
   - Для верификации веба в Safari использовать локальный сервер разработки `http://localhost:5173`.
