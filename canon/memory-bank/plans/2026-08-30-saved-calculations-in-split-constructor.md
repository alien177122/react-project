# План: сохранённые расчёты в конструкторе сплита

## Цель

Сделать в веб-конструкторе сплита полноценный вход в сохранённые расчёты: пользователь видит конкретные программы с упражнениями и параметрами, может открыть сохранённый расчёт, изменить его в конструкторе, пересчитать и обновить ту же запись либо удалить её с подтверждением. Название сплита должно явно поддерживать имя/фамилию человека и несколько расчётов для одного человека, при этом существующая persistence-модель и текущие русские UX-паттерны должны сохраниться.

## План работ

1. Проследить путь `SplitConstructorTab` от состояния формы до shared hook, API-нормализации и серверной схемы; определить, какие поля уже сохраняются в `splitCalculations`.
2. Проверить текущие UI-эталоны калькулятора и стили, затем спроектировать минимальное расширение существующей секции без параллельного store.
3. Реализовать отображение конкретных сохранённых расчётов, выбор/open, редактирование и пересчёт с обновлением выбранной записи, а также подтверждённое удаление.
4. Добавить или обновить focused-тесты для persistence и действий, если текущие тестовые паттерны это позволяют; обновить project memory progress/tasks.
5. Проверить typecheck, tests, lint (или targeted lint), запустить Vite и проверить desktop/390px сценарий через встроенный browser MCP или Playwright: save → visible → open → edit/recalculate → delete/confirm → removal → overflow.

## Критерий готовности

- В секции конструктора видны конкретные сохранённые расчёты с упражнениями/параметрами, а строки доступны с клавиатуры и имеют touch target не менее 44px.
- Открытие записи загружает её в конструктор; «Пересчитать» действительно сохраняет обновлённую запись, «Удалить» требует подтверждения, удаляет persistence и очищает выбранную запись.
- Поле «Название сплита» сопровождается коротким объяснением про фамилию/имя и несколько расчётов.
- `npm run typecheck`, `npm test` и `npm run lint` либо targeted lint имеют зафиксированный результат; desktop и 390px browser-проверка не выявляют горизонтального overflow.
- Теория, native archive, `.env` и `gym.db` не изменены; коммит не создаётся.
