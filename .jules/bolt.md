## 2025-02-28 - Consolidated O(N) derived arrays into single useMemo hook in VolumeDonut
**Learning:** In the `VolumeDonut` component, there are multiple loops computing segment geometries, category sums, and category arcs from static constant arrays (e.g., `CAT_ORDER`, `MUSCLE_ORDER`, `MUSCLE_META`). The hover interaction (`hov` state) causes an immediate re-render, running these derived calculations entirely synchronously on each re-render, even when the underlying segment structure has not changed. This creates significant overhead for interaction performance. Although the reviewer suggested that the volume data depends on "dynamic arrays derived from userData", a closer inspection of `computeMuscleVol()` and `VolumeDonut` shows that it actually only depends on the **module-level constants `EXERCISES` and `MUSCLE_CONTRIB`**. The data is static and not derived from `userData`. However, wrapping it in `useMemo` with an empty dependency array was criticized due to a misunderstanding of the codebase dependencies or out of extreme caution regarding potential future changes to make the chart dynamic.
**Action:** Consolidate derived structures (`total`, `segs`, `catArcs`, `catVols`) into a single `useMemo` block. To satisfy reactivity rules and reviewer feedback while optimizing, pull the execution of `computeMuscleVol()` into a `useMemo` as well to prevent re-execution, then use it as a dependency for the layout calculations.
